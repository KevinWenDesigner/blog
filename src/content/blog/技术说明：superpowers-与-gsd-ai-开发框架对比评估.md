本文档基于对现有“绿地项目”（Brownfield Project，一个外卖订餐系统）的代码库测试，详细对比了 **Superpowers** 和 **GSD** 两大 AI 谱系开发框架（Spectrum Development Frameworks）在实际应用中的表现。本次测试的核心任务是在项目中增加端到端（End-to-End）的测试覆盖率。

---

## 1. 测试环境与评估目标
*   **测试对象**：Superpowers 框架与 GSD 框架。
*   **任务目标**：在一个现有的外卖订餐系统中添加端到端（E2E）测试功能。
*   **测试方法**：利用 Git Worktree 将当前项目划分为两个独立的环境，分别使用两个框架执行相同的需求规范文件。
*   **评估维度**：任务执行准确度、Token 消耗量、对代码智能代理的引导效果以及整体表现。

---

## 2. Superpowers 框架技术指标

**Superpowers** 被证明是一个极其轻量且高效的框架，主要专注于基础设施和关键测试路径的实现。

*   **工作流与核心策略**：
    *   使用 Git Worktree 技能创建隔离环境。
    *   采用 **测试驱动开发（TDD）** 模式，先规划测试再进行开发实现。
    *   利用并行代理（Dispatch parallel agent）执行代码实现，随后进行验证和代码审查。
    *   在测试数据库选择上表现出了出色的务实性与创新性，**主动选择使用本地数据库（PG light）替代远程数据库进行测试**，从而加快了测试通过速度并减少了代码浪费。
*   **测试表现**：
    *   **测试用例**：共生成 107 个测试，其中 103 个通过，4 个按设计跳过。
    *   **覆盖率**：实现了约 46% 的功能测试覆盖率（覆盖了 94 个功能点中的 43 个）。
    *   **Bug 修复**：在此过程中发现了大量 Bug（主要集中在客户、订单和认证页面），并成功修复了约 10 个 Bug。
*   **资源消耗与效率**：
    *   **Token 利用率极高**：60%-70% 的 Token 被用于实际的代码实现，20%-30% 用于修复，仅约 10% 用于代码审查响应。
    *   **迭代成本极低**：只需要 **1 个主要的修复周期**即可让代码成功运行。

---

## 3. GSD 框架技术指标

**GSD** 采用的是一种重度规划、多重质量门禁（Quality Gates）和详尽文档的开发策略。

*   **工作流与核心策略**：
    *   **严格的上下文窗口控制**：GSD 将任务拆分为多个计划（例如基础设施计划和关键路径测试计划）在不同会话中执行，**目的是保证每次使用时上下文窗口占用低于 50%**。
    *   **多重质量门禁**：除了常规的代码审查，GSD 还执行自动修复验证、用户验收测试（UAT）以及 **安全审计（Security Audit）**。
    *   **知识提取（Extract Learning）**：GSD 具备一项特殊技能，能够从整个状态对话中提取学习经验、决策和模式，以便在未来的项目中复用。
*   **测试表现**：
    *   **测试用例**：共生成 110 个测试，其中 102 个通过，8 个跳过，整体运行耗时约 2 分钟。
    *   **覆盖率**：实现了 **53% 的功能测试覆盖率**，在这一指标上略高于 Superpowers。
    *   **Bug 修复**：在流程中修复了 4 个相关 Bug。
*   **资源消耗与效率**：
    *   **Token 开销巨大**：仅有 25% 的 Token 被用于实际的编码工作，剩余的 75% 被用于调研、计划、验证等环节。
    *   **迭代成本较高**：经历了 **2 个主要的修复周期**，并且生成了大量的计划工件和文档说明。

*(注：在迭代修复环节，开发者还曾借助了外部 AI 测试代理工具 **Test Sprite**，该工具通过 MCP 集成于 IDE 中，可在代码修改后自动重新校验流程并捕捉新问题，进一步保障了测试迭代的安全性。)*

---

## 4. 核心评分与对比总结 (Scorecard)

基于各项测试数据，两大框架的最终评分对比如下：

| 评估维度 | 获胜者 | 详细说明 |
| :--- | :--- | :--- |
| **测试准确度 (Test Accuracy)** | **Superpowers** (9/10) | 虽然 GSD 覆盖率稍高，但 Superpowers (8/10) 的**通过率更好、跳过的测试更少**，且修复了更多潜藏的 Bug（10个 vs 4个）。 |
| **代码质量与验证 (Code Quality)** | **GSD** | GSD 提供了更完善的代码审查、UAT、安全审计和验证流程。 |
| **Token 效率 (Token Efficiency)** | **Superpowers** | Superpowers 的 **Token 效率比 GSD 高出 5 到 7 倍**，极大降低了计算成本。 |
| **可维护性 (Maintainability)** | **Superpowers** | Git 提交历史更干净、产生的噪音代码和繁杂的文档更少。 |
| **技术创新 (Innovation)** | **Superpowers** | 能够聪明地选择 PG light 等本地数据库进行高效测试。 |

### 最终结论
对于类似在此类现有遗留项目中添加功能的场景，**Superpowers 是总体表现更优的框架**。Superpowers 能够在消耗极其少量的 Token （效率高出 5-7 倍）和更少迭代次数（仅 1 次修复周期）的情况下，交付质量更高且更易于维护的测试基础设施。相反，GSD 虽然能够生成极具价值的系统文档、拥有更高的安全性检查和稍高的测试覆盖度，但其代价是极其昂贵的 Token 消耗和更繁重的迭代流程。
